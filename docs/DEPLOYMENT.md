# Deploying Campus Marketplace to Vercel

A complete, copy-paste walkthrough for taking this project from your laptop to a
public URL with a real database and permanent image storage.

You do **not** need to change any code. You only need to create three accounts
(all have free tiers), paste six to twelve environment variables into Vercel and
run two commands once.

> **Do not deploy before the external services exist.** Set the environment
> variables first (Step 4) — the app is designed to boot even with missing
> settings, but uploads and database calls will not work until they are filled
> in. `/api/health` tells you exactly what is wrong.

---

## 1. What "hosted" looks like

```
                    ┌──────────────────────────────┐
   browser ────────▶│  Vercel                      │
                    │                              │
                    │  public/**   → static site   │  (generated by build_vercel.py)
                    │  /api/**     → app.py        │  (Flask, one Vercel Function)
                    └───────┬──────────────┬───────┘
                            │              │
              DATABASE_URL  │              │  S3_* (UPLOAD_STORAGE=s3)
                            ▼              ▼
                  managed PostgreSQL   S3-compatible bucket
                  (Neon / Supabase)    (Cloudflare R2 …)
```

Three externally hosted pieces:

| Piece | What it stores | Recommended free option |
|---|---|---|
| Vercel | the app/API + static site | Hobby plan |
| Managed PostgreSQL | users, listings, reviews… | [Neon](https://neon.tech) |
| S3-compatible bucket | uploaded photos | [Cloudflare R2](https://developers.cloudflare.com/r2/) |

Why not the SQLite file and `frontend/assets/uploads` used locally? Vercel runs
your code in a function whose filesystem is **read-only except `/tmp`**, and
`/tmp` is wiped between requests. Anything written there disappears, so both the
database and the images must live outside the app.

- [ ] This repository pushed to GitHub (it is).

## 3. Create the PostgreSQL database

Using Neon (the same idea applies to Supabase or Vercel Postgres):

1. Sign in to <https://console.neon.tech> and choose **New Project**.
2. Project name: `campus-market`. Pick the region closest to your users
   (`Europe (Frankfurt)` or `AWS us-east-1` are good for Nigeria/Vercel — Vercel
   functions default to Washington, D.C., so `us-east-1` keeps them close).
3. Copy the **connection string** from the dashboard. It looks like:

   ```
   postgresql://neondb_owner:AbC123...@ep-cool-name-123456.us-east-1.aws.neon.tech/neondb?sslmode=require
   ```

   Keep `?sslmode=require` — managed databases require TLS.
4. That whole string is your `DATABASE_URL`. The app automatically rewrites
   `postgresql://` to `postgresql+psycopg://`, so paste it exactly as Neon gives
   it to you.

> **Password characters:** if your database password contains `@`, `:` or `/`,
> URL-encode it (`@` → `%40`). Simplest fix: reset the password to something
> alphanumeric.

> **Supabase users:** copy the *Connection pooling* → *URI* string (port `6543`)
> if available; it survives serverless traffic better.

---

## 4. Create the S3-compatible bucket (Cloudflare R2)

Cloudflare R2 has no egress fees and a generous free tier, which is why it is
the recommended option. AWS S3, MinIO, Backblaze B2 and Supabase Storage's S3
gateway all work the same way — only the endpoint and credentials change.

1. In the Cloudflare dashboard open **R2 → Create bucket**.
   - Name: `campus-market` (lowercase, no spaces).
   - Location: `Automatic`.
2. Open the bucket → **Settings → Public access** → enable the **R2.dev
   subdomain** and copy the URL, e.g. `https://pub-1a2b3c4d5e.r2.dev`.
   This becomes `S3_PUBLIC_BASE_URL`, and it is what makes
   `https://pub-…r2.dev/uploads/u3_….png` load in the browser.
   *The `r2.dev` URL is rate-limited and meant for development/demo use; later
   you can attach a custom domain to the bucket and swap this value.*
3. Get credentials: **R2 → API → Manage API tokens → Create API token**.
   - Name: `campus-market-app`
   - Permissions: **Object Read & Write**
   - Scope: **Apply to specific buckets → `campus-market`**
   - Copy the **Access Key ID** and **Secret Access Key** (the secret is shown
     only once).
4. Note your account ID (it is in the R2 overview / dashboard URL):
   `S3_ENDPOINT_URL` = `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

Result — five values to remember:

| Variable | Example |
|---|---|
| `S3_BUCKET` | `campus-market` |
| `S3_ENDPOINT_URL` | `https://1a2b3c4d5e6f.r2.cloudflarestorage.com` |
| `S3_ACCESS_KEY_ID` | `a1b2c3…` |
| `S3_SECRET_ACCESS_KEY` | `d4e5f6…` |
| `S3_PUBLIC_BASE_URL` | `https://pub-1a2b3c4d5e.r2.dev` |

## 5. Generate the two secrets

Run this twice and keep both outputs (they must be different):

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

- `SECRET_KEY` — Flask session/CSRF signing key.
- `JWT_SECRET` — signs login tokens. Changing it logs everybody out.

## 6. Import the project into Vercel

1. Go to <https://vercel.com/new> and import the `campus-market-hub` repository.
2. **Framework Preset**: Vercel detects **Flask** automatically (the root
   `app.py` exposes the WSGI `app`). Leave *Build & Output Settings* on their
   defaults — `vercel.json` supplies them:
   - Build command: `python build_vercel.py` (generates `public/`)
   - `public/**` is served from the CDN, everything else goes to Flask.
3. Do **not** click Deploy yet — add the environment variables first
   (Step 7). If you already deployed, that is fine: add them, then *Redeploy*.

---

## 7. Environment variables (Vercel → Project → Settings → Environment Variables)

Add each row for the **Production**, **Preview** and **Development**
environments. `public/` is generated, so nothing else is needed for the static
site.

| Variable | Value | Required |
|---|---|---|
| `FLASK_ENV` | `production` | yes |
| `DATABASE_URL` | the Neon string from Step 3 | yes |
| `SECRET_KEY` | first random string from Step 5 | yes |
| `JWT_SECRET` | second random string from Step 5 | yes |
| `UPLOAD_STORAGE` | `s3` | yes (persistent images) |
| `S3_BUCKET` | `campus-market` | yes when `UPLOAD_STORAGE=s3` |
| `S3_ENDPOINT_URL` | `https://<account>.r2.cloudflarestorage.com` | yes for R2 |
| `S3_ACCESS_KEY_ID` | R2 token access key | yes when `UPLOAD_STORAGE=s3` |
| `S3_SECRET_ACCESS_KEY` | R2 token secret | yes when `UPLOAD_STORAGE=s3` |
| `S3_PUBLIC_BASE_URL` | `https://pub-….r2.dev` | yes (otherwise images cannot be linked) |
| `S3_REGION` | `auto` | optional (default `auto`) |
| `S3_PREFIX` | `uploads` | optional (default `uploads`) |
| `S3_ADDRESSING_STYLE` | `path` | optional; use `virtual` for AWS S3 |
| `MAX_UPLOAD_MB` | `4` | optional; clamped to 4 MB on Vercel |
| `CORS_ORIGINS` | e.g. `https://your-app.vercel.app` | optional (default `*`) |
| `AUTO_PUBLISH` | `false` | optional (moderation stays on) |

Notes:

- Vercel's own Postgres/Neon integration exports `DATABASE_URL` too; if you use
  it, confirm the value in **Settings → Environment Variables** rather than
  adding a second one.
- 4 MB is the practical upload ceiling: Vercel rejects request bodies larger
  than ~4.5 MB before Flask sees them, so the app clamps `MAX_UPLOAD_MB` for you.
- Keep `AUTO_PUBLISH=false` so every student listing is reviewed by an admin.

Deploy now (**Deploy** / **Redeploy**), and wait for the build to finish. The
first deployment should log *"Running on Vercel – upload storage: s3"*.

## 8. Create the tables (`init-db`)

The schema is created by a command, not automatically, so that nothing is
dropped or seeded by accident. Run it **from your laptop**, pointing at the
managed database (the Neon URL includes `?sslmode=require`, so it works from
anywhere):

```bash
cd campus-market-hub
source .venv/bin/activate        # Windows: .venv\Scripts\activate

export DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require"
export FLASK_ENV=production

flask --app app init-db
# → Database tables created.
```

Alternative: `vercel env pull .env.local` downloads the project variables into
`.env.local`, but exporting `DATABASE_URL` yourself is simpler for one command.

---

## 9. Create your administrator (`create-admin`)

Still in the same terminal, with the same `DATABASE_URL` exported:

```bash
flask --app app create-admin --email you@example.com --name "Your Name"
```

The command prints a generated password — **save it** (it is only shown once).
Prefer choosing your own password (at least 6 characters, letters + digits)?

```bash
flask --app app create-admin --email you@example.com --password "YourPass123"
```

Facts worth knowing:

- No account is created automatically: no default `admin@…` login, no seeded
  users, no demo listings. `create-admin` is the only way an admin appears.
- Re-running it for an existing email promotes the account to admin and keeps
  the password unless you pass `--password` or `--reset-password`.
- On your laptop the same commands work against the local SQLite file
  (`flask --app app init-db` with no `DATABASE_URL` set).

Log in at `https://<your-project>.vercel.app/pages/login.html` with that email
and password, then open the admin dashboard.

## 10. Smoke test the deployment

| # | Check | Expected |
|---|---|---|
| 1 | `GET /api/health` | `status: "ok"`, `database: "connected"`, `storage.backend: "s3"`, `storage.persistent: true`, no `warnings` |
| 2 | Open `/` | Landing page loads with styling (served from the CDN) |
| 3 | Log in as the admin | Dashboard loads, stats are zeros |
| 4 | Student sign-up, post a product **with a photo** | Upload succeeds; the image URL starts with your `S3_PUBLIC_BASE_URL` |
| 5 | Check the R2 bucket | An object `uploads/u<id>_…png` exists |
| 6 | Approve the listing as admin | It becomes public |
| 7 | Redeploy (push any commit) and reload the listing | The image is still there (this is the persistence test that `/tmp` would fail) |
| 8 | `/api/health` from a phone | Same JSON — proves the environment variables are set for Production, not only Preview |

## 11. Updating the site

- **Frontend changes** (`frontend/**`): edit, commit, push. Vercel re-runs
  `python build_vercel.py` and republishes `public/`. Never edit `public/` by
  hand — it is generated and git-ignored.
- **Backend changes** (`backend/**`): same — push and Vercel redeploys the
  function.
- **Schema changes**: run `flask --app app init-db` again (it only creates
  missing tables; brand-new columns on existing tables need a migration, which
  is outside this course project's scope).

Local development is unchanged: `python app.py` from the repository root (or
`cd backend && python app.py`) still serves the API *and* the frontend at
<http://localhost:5000>, using SQLite and `frontend/assets/uploads`.

## 12. Troubleshooting

| Symptom | Cause & fix |
|---|---|
| `/api/health` → `database: "error: …"` | `DATABASE_URL` is wrong, or the database is asleep. Neon free branches suspend after inactivity; the first request wakes them (that is why the function has a 30 s limit). |
| `/api/health` → `storage.configured: false` | `UPLOAD_STORAGE=s3` but `S3_BUCKET` / `S3_PUBLIC_BASE_URL` are missing. The error message names the missing variable. |
| Upload returns `503` with *"Check S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY"* | The R2 token is wrong, expired, or scoped to another bucket. Create a new token with **Object Read & Write** on that bucket. |
| Upload succeeds but the image is broken (404) | The bucket is not public, or `S3_PUBLIC_BASE_URL` does not match the bucket's public URL. Open `S3_PUBLIC_BASE_URL/uploads/<filename>` directly to confirm. |
| Upload fails at exactly ~4 MB with an HTML error | Vercel's request-body limit was hit. Keep `MAX_UPLOAD_MB<=4`; for bigger images you would need client-side uploads directly to R2 (out of scope). |
| `GET /pages/...` returns JSON `{"success": false, "message": "Not found"}` | The page does not exist in `public/`. Run `python build_vercel.py --check` locally — `frontend/` is the source of truth. |
| Deploy succeeds but the site is an unstyled page / 404 | Check the build log: `python build_vercel.py` must have run and created `public/`. Committing a `vercel.json` with a wrong `outputDirectory` breaks this — keep the repository's file as-is. |
| `ModuleNotFoundError: psycopg` / `boto3` in the build log | The root `requirements.txt` is the file Vercel installs; do not replace it with `backend/requirements.txt`. |
| "No administrator account yet" on `/pages/login.html` | Run Step 9 (`create-admin`) with the production `DATABASE_URL` exported. |
| Password reset / lost admin password | `flask --app app create-admin --email you@example.com --reset-password` (with the production `DATABASE_URL`). |

## 13. Free-tier reality check

> Allowances below are indicative (checked at the time of writing) — confirm the
> current numbers on each provider's pricing page.

| Service | Free allowance | What it means here |
|---|---|---|
| Vercel Hobby | 1 M function invocations, 100 GB transfer | Plenty for a course demo; function max duration 30 s (set in `vercel.json`). |
| Neon | 1 project, autosuspends | Wakes in <1 s on the first request after idle. |
| Cloudflare R2 | 10 GB storage, no egress fees | Thousands of listing photos. `r2.dev` URLs are rate-limited — attach a custom domain for real traffic. |

When you are ready for a custom domain: **Vercel → Project → Domains** for the
site, and **R2 → bucket → Settings → Custom Domains** for images (then update
`S3_PUBLIC_BASE_URL`).

```bash
# 1. local sanity check
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s backend/tests
.venv/bin/python build_vercel.py

# 2. (Vercel dashboard) import repo, add the variables from Step 7, deploy

# 3. from your laptop, against the managed database
export DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require"
export FLASK_ENV=production
.venv/bin/flask --app app init-db
.venv/bin/flask --app app create-admin --email you@example.com
```

Then open `https://<your-project>.vercel.app/api/health` and confirm
`"status": "ok"` with `"storage": {"backend": "s3", "persistent": true, …}`.
